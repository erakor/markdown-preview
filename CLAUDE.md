# CLAUDE.md

Native macOS port of understood/markdown-preview. SwiftUI shell, NSTextView editor, WKWebView preview running the same JS pipeline as the web tool.

## Linux / macOS split
- Cloud sessions run on Linux: **Swift, AppKit and SwiftUI cannot be built there.** The macOS CI job (`macos-15`) is the only verification loop for Swift code. Push and read the Actions result; do not claim Swift compiled until it did.
- The Xcode project is generated by XcodeGen from `project.yml`. Never commit `*.xcodeproj`.
- `renderer/` is a Node package that **can** be built and tested on Linux. Containers with only Chromium: `CHROMIUM_PATH=/opt/pw-browsers/chromium pnpm exec playwright test --project=chromium --trace off` (CI uses `pnpm test:e2e --project=webkit`). It needs Node 26 (`.nvmrc`) and pnpm (`packageManager` in `renderer/package.json`, run `corepack enable`); after a change run `pnpm lint && pnpm format:check` too.

## Committed renderer bundle
`App/Resources/Renderer/` is build output of `renderer/` and is committed so the Xcode build needs no Node. After any change in `renderer/src` run `cd renderer && pnpm build` and commit the result; CI fails on a stale bundle.

## Shared tooling
Lint, format, TypeScript, editor and Swift format settings come from [erakor/toolchain](https://github.com/erakor/toolchain), a git dependency pinned to a commit in `renderer/package.json` (the CI workflow pins the same commit). `.oxlintrc.json` extends its `oxlint/base.json`, `oxfmt.config.ts` spreads its `oxfmt` export (oxfmt only finds that name or `.oxfmtrc.json`), and `.editorconfig`, `.gitattributes` and `.swift-format` are copies of its `files/` and `swift/`: change those there, not here. A rule or option this repo alone needs goes in its own config, on top. A deliberate lint exception is `// eslint-disable-next-line <rule> -- <reason>`; lint runs with `--report-unused-disable-directives`, so a stale one fails. `src/preview.html` is kept out of oxfmt because it is copied verbatim into the committed bundle. A style-only reformat goes in a commit of its own, with its hash added to `.git-blame-ignore-revs`.

## Invariants
- **Sanitization is not optional.** marked output always goes through DOMPurify before `innerHTML`. Never add a path that skips it.
- **Mermaid version counter.** `mermaidRenderVersion` cancels stale renders; keep the checks after every `await`. Mermaid runs with `securityLevel: 'strict'`.
- No CSS reset (no Tailwind Preflight): github-markdown CSS relies on browser defaults for lists and inline images. The bare `p { margin: 1em }` rule is deliberate.
- Swift values reach JS only as `callAsyncJavaScript` arguments, never spliced into script text.
- The scheme handler must refuse `..` traversal (tested in `LocalFileSchemeHandlerTests`).
- Vendored `renderer/src/vendor/github-markdown-*.css` are copies from the upstream repo; do not regenerate them from the network.

## Not ported on purpose
Vercel analytics, Monaco, the localStorage legacy-key fallback, the `com.markdownlivepreview` namespace, Tailwind.
